# Upgrading to CopyTyGo v3

CopyTyGo v3 uses Go semantic import versioning:

```text
github.com/arfajhf/copytygo/v3
```

## Module imports

Update framework imports from:

```text
github.com/arfajhf/copytygo/v2/...
```

to:

```text
github.com/arfajhf/copytygo/v3/...
```

Then update the dependency:

```powershell
go get github.com/arfajhf/copytygo/v3@latest
go mod tidy
```

Install the v3 CLI:

```powershell
go install github.com/arfajhf/copytygo/v3/cmd/ctg@latest
```

## Production changes

v3 adds:

- request IDs and structured request logging
- server timeouts and graceful shutdown
- generated soft deletes
- paginated/searchable/filterable/sortable resources
- stronger signed-token key requirements
- production migration safeguards
- `ctg doctor --production`

## Generated resources

New v3 resources include a nullable `deleted_at` column. DELETE requests generated by v3 soft-delete the row instead of physically removing it.

Existing v2 resources are not automatically modified. Add a `deleted_at` migration intentionally if you want to adopt v3 soft-delete behavior in an existing table.

## Auth key

v3 signed tokens require an application key of at least 32 characters.

Generate a new key when necessary:

```powershell
ctg key:generate
```

Changing `APP_KEY` invalidates previously signed tokens.

## Migration commands in production

When `APP_ENV=production`, destructive operations require `--force`:

```powershell
ctg migrate:rollback --force
ctg migrate:reset --force
ctg migrate:fresh --force
```

## Verification

After upgrading:

```powershell
ctg doctor --db --production
ctg route:list
ctg migrate:status
ctg build
```

Verify the generated application health endpoint before sending production traffic.
